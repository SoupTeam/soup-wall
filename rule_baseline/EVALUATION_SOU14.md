# SOU-14 development evaluation of the generic classifier

Generated by `evaluate_dev.py` (scoring version 2). Re-run it after any change to the classifier; the hashes below say what was measured.

## Read this first

- **Development numbers, not a held-out result.** The train, validation and calibration splits were all
  visible while the rules were written, so none of them is held out from the classifier. The closed test
  (54 cases) is held by its custodian and was not used here.
- **Provisional labels.** Every case carries `label_status: provisional`, and the exports measured here
  predate the final dev-export and gold addendum. A "miss" can also be a label question.
- **Partial labels.** Some cases have actions whose truth is not established (target null, `known_mask` 0).
  Those actions are not scored as right or wrong; the tables below say how many known labels each number rests on.
- **Synthetic data.** All cases come from the SOU-13 synthetic generator (`example.test` domains only);
  they say little about the frequency of real tools.
- **Denominators are cases, not tools.** Several cases share a template or family, so counts are not
  independent samples.

## What changed from the first report

The first report ([EVALUATION_SOU14_e4e494a.md](EVALUATION_SOU14_e4e494a.md), superseded) came from the same development exports and the same classifier file (sha256 above), scored by an earlier `evaluate_dev.py`.
- **Contract match is unchanged:** candidate 143/188, baseline 109/188, always abstain 24/188, always no-effect 19/188.
- **Per-label numbers changed.** Actions whose truth is not established (target null, `known_mask` 0) are no longer counted as false; each row now shows its known-true, known-false and unknown-target counts, and extra reports (fp) are only counted on known-false labels.
- **Outputs are validated.** Missing or malformed output, an explicit error and a raised exception are technical failures against the case totals, never a no-op answer.
- **Latency method changed.** Only valid completed exchanges are timed, with bounded request and cleanup time; failed and timed-out attempts are reported with attempt counts. The old claim that the cold-process figure is an upper bound is withdrawn.
- **One captured source.** The bytes that are hashed are the bytes compiled and the bytes run in the snapshot processes; a cached `.pyc` is never used.
