# Original Git read outcomes

The SOU-177 diagnostic records distinguish call admission, the original response, profile validation, result inspection and delivery. They contain correlation hashes, response hashes, protocol-error codes and Boolean observations. Policy reason codes are represented by a digest of the exact reason array. Original content, exception messages, arguments and credentials are not diagnostic fields.

`mcp_call_outcome` version 1 is an observation, not authority to execute or release content. A server tool error and an inspection refusal are different outcomes. A successful negative control is not useful Git work.

The existing project qualifier retains these records as `boundary_observations`. It reconstructs successful stderr writes from identified collector processes, including fragmented and short writes. The collector's server role comes from its observed process launch, overriding any self-reported role. Operations are correlated through independently observed original-server calls, exact tool/argument bindings, the actual JSON-RPC ID and the exact request-frame digest. Reused IDs cannot mix records across servers or different request frames. Model tool-use IDs are not assumed to be RPC IDs. Unknown fields and arbitrary server text are discarded. Missing observations remain missing and must not be used to infer a failure boundary.

`accepted` at profile validation means that the response shape passed validation. `released` describes the admission or inspection decision at its stated stage. Only a separate delivery observation with `written=true` records a completed host write. None of these records grants authority.

Each correlated operation includes `failure_boundaries`: a finite list of observed admission, upstream protocol/tool, profile, inspection or delivery failures. Multiple failures remain visible. An empty list does not prove success when records are missing. In particular, a server tool error does not establish a sandbox defect, and absence of a delivery record does not establish a failed write.

Each case retains up to 256 observations in numbered JSON files, with at most 32 records per file. The main report stores their names, offsets and SHA-256 digests; operation indices refer to the concatenated records. This avoids duplicating large records and preserves the existing 64 KiB file limit. The final report uses compact JSON with the same fields and values. Installation manifests retain their existing default encoding and byte identity. Failed host outcomes retain the same diagnostic files. An incomplete dispatch observer remains a qualification failure, and its negative dispatch observations are unknown rather than false.

Run the targeted `mcp-real-filesystem.yml` workflow with `existing_project_only=true` to exercise the existing project lane and the unchanged docs-code, unicode-spaces and local-history inventories. The added project inventory and observer controls run only in this explicit mode; `native_preparation_only` retains the legacy lane. The `--git-negative-controls` option appends five controls after the original operations: an absent Git revision, unsupported Git path/expression syntax, a real nonempty tree object supplied by its full OID, and an absent workspace file. The tree OID comes from the owned fixture using the selected pinned Git. It is not substituted for an original useful call.

Error and dispatch observations are reported separately in `additional_negative_controls`; they are never counted as useful work. Unsupported Git path/expression dispatch fails qualification. The real tree exercises the original server's object error rather than assuming that every negative request must be refused before dispatch. Client error classes retain only fixed known message labels; they are presentation observations, not policy authority. Per-call boundary indices remain the diagnostic evidence. Existing destructive-tool, outside-read and network witnesses remain required. No timeout is increased.

Keep failed reports and exact source/input identities. No detector correction or successful utility claim is established by diagnostic instrumentation alone. A mismatch between a healthy original response and a refused inspected result must be attributed to the selected inspection rule before any detector handoff; do not change rules to make the qualifier pass.
