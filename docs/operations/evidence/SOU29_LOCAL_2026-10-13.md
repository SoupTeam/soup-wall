The disposable-profile scenarios cover a wrong expected digest, missing
candidate, repeat installation and start, successful start, upgrade and
rollback, an executable that fails to start, recovery after interrupted
activation and staging, a foreign listener, binary-name/path validation,
stop and restart, and removal. The end-to-end runs assert that the previous
version is running after a failed upgrade. They also check that managed
binaries are removed while configuration, token, audit log and an unrelated
file remain. The interrupted-staging test leaves a similarly named foreign
file untouched.

The managed health response binds a random instance to the PID, binary
digest and startup configuration. Shutdown uses that authenticated instance;
no command kills a process by PID alone. The status output reports
configuration drift and foreign-port conflicts. A live recorded PID whose
identity cannot be verified blocks recovery.

## Limits

Windows execution used a local cross-built binary and a native Windows host.
Windows was not rerun after the rebase. macOS was not available locally; the
PR's dedicated macOS job will run the lifecycle test and retain its log,
environment and binary digest. A passing CI result is still required before
macOS can be claimed as verified. The existing live-model test was not run.
