## Findings, repair and honest effects

**SOU-44 — admitted FIFO replacement.** Original main accepted the declared regular
leaf, then an owned proxy substituted a FIFO after authentic Allow. A blocking
leaf open prevented the regular-file check; the gateway remained alive without
a response for more than four seconds. The original fail remains preserved.
The repair adds nonblocking leaf open while retaining no-follow/pinned-root checks,
then refuses the non-regular descriptor before reading. Final native/MCP regression
returns the correlated read failure, withholds original contents and proves a
useful regular-file read in the same session. The deliberate fixture substitution
is separate from tool effects; it is not a claim of no filesystem changes anywhere.

**SOU-45 — unsupported overlap.** Original main processed two requests queued
before either response. The first repair refused overlap during classification,
native call/result gates and inline reads. Independent review then exposed a
remaining reply-write gap: while a permitted result over 208 KB was blocked on
stdout, 65,536 bytes had already entered the pipe; a second request sent before
completion later received its own read/result. The captured production-source
hashes match committed `28001eb` despite a stale raw descriptive label referring
to an uncommitted patch. The intermediate candidate is rejected and retained.

Final resource reply writing observes queued input through completion/drain,
retains one in-progress write across EOF and distinguishes completed sequential
replies from unsupported overlap. At the actual boundary:

- Complete or partial queued second calls before execution produce no native
  gates, child calls, receiver deliveries or protected result bytes.
- Classification and native admission/result stage tests refuse unsupported
  complete/partial overlap and cancellation; useful peers remain available.
- Large-reply complete-call, partial-call and cancellation cases record **one
  already-permitted broker read**, two native gates and an ended session before
  the verifier resumes draining. No second call is admitted or released. The
  already-produced first content and its 65,536 exposed pipe bytes are retained
  honestly; the final transcript may finish that permitted first reply on drain.
  Do not describe these cases as zero execution or zero first-result bytes.
- A fully drained large reply followed by another sequential read produces both
  exact useful responses. Client EOF after the first request finishes that
  reply exactly once; no duplicate frame or effect is accepted.
- Seventy admitted read failures preserve their correlated errors and a useful
  same-session follow-up, with 71 classifications and 142 native gates.

This is explicit refusal of unsupported overlap/cancellation, not support for
parallel execution, immediate cancellation or rollback. Shared Deny and
